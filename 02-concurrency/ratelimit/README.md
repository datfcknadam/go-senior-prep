# Задача: rate limiter (token bucket)

Ведро вмещает `burst` токенов и пополняется со скоростью `rate` токенов в секунду.
Каждый запрос забирает один токен. Нет токена — запрос отклоняется (`Allow`) или ждёт (`Wait`).

```go
l := NewWithClock(rate, burst, now) // now — функция времени, чтобы тест не зависел от часов
l.Allow() bool
l.Wait(ctx) error                   // ждёт токен или отмену ctx
```

Требования:

- Пополнение считается **лениво** при каждом вызове по прошедшему времени — никаких тикеров и фоновых горутин.
- В начале ведро полное.
- Потокобезопасность.
- `Wait` при отменённом контексте возвращает `ctx.Err()` и не забирает токен.

Вопросы для обсуждения (это уже system design):

- Token bucket vs leaky bucket vs fixed window vs sliding window log / counter. Плюсы и минусы.
- Как сделать лимит **на пользователя**? Как не утечь памятью с миллионом пользователей?
- Как сделать лимит **на кластер** из 50 подов? (Redis + Lua-скрипт, приблизительные локальные лимиты = общий / N)
