# Задача: worker pool

Классическая задача live coding: «есть N URL (id объявлений, …), обработай их параллельно, но не больше K одновременно».

```go
func Process[In, Out any](
    ctx context.Context,
    inputs []In,
    workers int,
    fn func(context.Context, In) (Out, error),
) ([]Out, error)
```

Требования:

1. Одновременно выполняется не больше `workers` вызовов `fn`.
2. `results[i]` соответствует `inputs[i]` — порядок сохраняется.
3. При первой ошибке: остальным вызовам отменяется контекст, новые задачи не запускаются,
   функция возвращает **эту первую** ошибку.
4. При отмене внешнего `ctx` — возвращается `ctx.Err()`.
5. Когда `Process` вернул управление, ни одна запущенная им горутина больше не работает.

Сначала напиши руками на `sync.WaitGroup` + каналах. Потом — на `golang.org/x/sync/errgroup`
(`SetLimit`) и сравни, сколько кода ушло.

Вопросы:

- Почему запись `results[i] = ...` из разных горутин — не гонка?
- Сколько воркеров ставить для CPU-bound и для IO-bound задач?
- Что делать, если входов миллион и их нельзя держать в памяти? (стриминг через каналы, backpressure)
