# 09. Финальный проект: сервис продвижения объявлений

Многие компании публикуют тестовые задания для стажёров на GitHub (поищи `backend-trainee-assignment`) — посмотри пару для понимания стиля.
Здесь задание в том же духе, но с требованиями уровня senior. Цель — не «сделать фичи», а получить проект,
о котором можно 20 минут уверенно рассказывать на собеседовании: почему именно так, что будет под нагрузкой и при отказах.

Код пиши в `09-final-project/` (свой `go.mod` или в общем модуле — на твой выбор).

## Предметная область

Пользователь может купить для своего объявления платную услугу «Поднятие» за деньги со своего внутреннего кошелька.
Поднятое объявление 24 часа показывается выше в выдаче категории.

## Функциональные требования

1. `POST /wallets/{user_id}/deposit` — пополнение кошелька (имитация платежа).
2. `GET /wallets/{user_id}` — баланс и история операций с пагинацией.
3. `POST /promotions` — купить поднятие: `{ad_id, user_id}`, заголовок `Idempotency-Key`.
   - нельзя купить, если не хватает денег;
   - повторный запрос с тем же ключом возвращает тот же результат и не списывает деньги второй раз;
   - нельзя купить для чужого объявления.
4. `GET /categories/{id}/feed?cursor=...` — выдача: сначала активные поднятые (по времени покупки), затем остальные по дате. Keyset-пагинация.
5. По истечении 24 часов продвижение завершается само.
6. Событие `promotion.activated` публикуется в Kafka (через transactional outbox).

## Нефункциональные требования

- Go, PostgreSQL, Kafka (Redpanda в docker-compose подойдёт), `docker compose up` поднимает всё.
- Деньги — в копейках (`int64`), учёт в виде проводок (ledger), баланс не может стать отрицательным даже при 100 параллельных покупках.
- Целевая нагрузка на выдачу — 1000 RPS при p99 < 100 мс на ноутбуке. Подтвердить нагрузочным тестом (k6 / vegeta) и приложить результат.
- Graceful shutdown, таймауты на всё, контекст везде.
- Метрики Prometheus (RED), структурированные логи (`log/slog`), pprof на отдельном порту.
- Тесты: юнит-тесты бизнес-логики + интеграционные с Postgres через testcontainers, тест на конкурентную покупку. `go test -race` зелёный.
- Миграции (goose / golang-migrate), линтер (`golangci-lint`), Makefile.

## Что подготовить для рассказа

В `09-final-project/DESIGN.md` опиши:

1. Схему данных и почему такие индексы (с `EXPLAIN` для выдачи).
2. Как гарантируется, что деньги не спишутся дважды и баланс не уйдёт в минус (какой уровень изоляции/блокировки, почему).
3. Как работает outbox и что будет, если Kafka недоступна час.
4. Как завершаются продвижения и что будет, если этот процесс запущен в 3 подах одновременно.
5. Результаты нагрузочного теста, найденное узкое место и что сделал (профиль до и после).
6. Что бы поменял при 100× нагрузке.
