# Глава 2. Типы, значения, константы

## Зачем

Система типов Go маленькая, но строгая: неявных конверсий нет, у каждого типа есть нулевое значение, а «передача по ссылке» —
миф. Из этих правил выводятся ответы на половину вопросов «что выведет этот код».

---

## 1. Переменные 🟢

```go
var a int            // zero value: 0
var b, c = 1, "x"    // тип выводится
d := 3.14            // короткое объявление — только внутри функций
var (
    host = "localhost"
    port = 8080
)
```

- `:=` объявляет **хотя бы одну новую** переменную слева. Остальные просто присваиваются, если объявлены в **той же** области видимости.
- **Затенение (shadowing)** — частый источник багов:
  ```go
  var err error
  if cond {
      x, err := f() // новый err во внутренней области! внешний останется nil
      _ = x
  }
  return err
  ```
  Линтер `govet -shadow` и внимательность на ревью.
- Идентификатор `_` отбрасывает значение: `_, err := f()`.

## 2. Нулевые значения 🟢

У каждого типа есть **zero value**, и переменная никогда не бывает «неинициализированной»:

| Тип | Zero value |
|---|---|
| числа | `0` |
| `bool` | `false` |
| `string` | `""` |
| указатель, слайс, мапа, канал, функция, интерфейс | `nil` |
| массив, структура | все элементы или поля — zero value |

Хороший API делает нулевое значение **полезным**: `var mu sync.Mutex`, `var buf bytes.Buffer`, `var sb strings.Builder`
готовы к работе без конструктора. Твои типы тоже должны вести себя так, где это возможно.

Но не всё работает с nil: чтение из nil-мапы возвращает zero value, а запись в неё — panic. Подробно в главе 4.

## 3. Базовые типы 🟢

| Группа | Типы |
|---|---|
| целые со знаком | `int8`, `int16`, `int32` (= `rune`), `int64`, `int` (размер слова: 64 бита на amd64/arm64) |
| беззнаковые | `uint8` (= `byte`), `uint16`, `uint32`, `uint64`, `uint`, `uintptr` |
| вещественные | `float32`, `float64` |
| комплексные | `complex64`, `complex128` |
| прочие | `bool`, `string` |

- **Неявных конверсий нет совсем**, даже между `int` и `int64`: `var x int64 = y` при `y int` не скомпилируется. Пишут `int64(y)`.
- Целые **переполняются циклически, без паники**: `int8(127) + 1 == -128`. Для денег это значит «проверяй границы» или используй
  целые копейки в `int64` и проверку переполнения.
- Деление целого на ноль даёт panic (если делитель — константа, то ошибку компиляции). Для float получится `+Inf` или `NaN`.
- `NaN != NaN`. Поэтому NaN-ключ в мапе нельзя ни найти, ни удалить (только `clear`).
- **Деньги никогда не хранят во float**: `0.1 + 0.2 != 0.3`. Целые минимальные единицы (копейки) или decimal-библиотека.
- Сдвиг на отрицательную величину — panic. Сдвиг влево на ≥ ширины типа даёт 0, вправо — 0 или −1 для отрицательных (знаковый сдвиг).
- Битовые операции: `&`, `|`, `^` (XOR, унарно — NOT), `&^` (AND NOT, сброс битов), `<<`, `>>`.

## 4. Константы и iota 🟢

- Константы вычисляются при компиляции. **Нетипизированные** константы имеют произвольную точность до момента использования:
  ```go
  const big = 1 << 100   // ок
  fmt.Println(big >> 98) // 4 — вычислено при компиляции
  // var x int = big     // ошибка: overflow
  ```
- Нетипизированная константа принимает тип по месту: `const d = 5` подходит и к `time.Duration`, и к `float64`.
  Поэтому `time.Sleep(5 * time.Second)` работает, а `n := 5; time.Sleep(n * time.Second)` — нет (`int` * `Duration`).
- **iota** — счётчик внутри блока `const`, начинается с 0 и увеличивается на каждой строке:
  ```go
  type Status int

  const (
      StatusUnknown Status = iota // 0 — нулевое значение = «не задано», это хорошая практика
      StatusActive                // 1
      StatusBlocked               // 2
  )

  type Perm uint8

  const (
      PermRead Perm = 1 << iota // 1
      PermWrite                 // 2
      PermExec                  // 4
  )

  const (
      _  = iota
      KB = 1 << (10 * iota) // 1024
      MB                    // 1048576
  )
  ```
- Строковое имя для enum генерирует `stringer` (`//go:generate stringer -type=Status`).

## 5. Объявление типов и алиасы 🟢

```go
type UserID int64        // НОВЫЙ тип: underlying int64, методов int64 нет, нужна явная конверсия
type Celsius float64

type Bytes = []byte      // АЛИАС: то же самое имя для того же типа
type Set[T comparable] = map[T]struct{} // дженерик-алиас, Go 1.24+
```

- Новый тип защищает от перепутывания: функцию `Ban(id UserID)` нельзя случайно вызвать с `ItemID`.
- **Underlying type** определяет, какие операции разрешены и между чем возможна конверсия: `UserID(5) + 1` можно, `UserID(x) + ItemID(y)` — нет.
- Алиасы нужны для постепенного рефакторинга (тип переехал в другой пакет) и для коротких имён. В обычном коде новые типы полезнее.

## 6. Указатели 🟢

```go
x := 10
p := &x      // *int
*p = 20      // x == 20
q := new(int)            // указатель на zero value
r := new(42)             // Go 1.26: new(expr) — указатель на значение выражения
```

- Арифметики указателей нет (кроме `unsafe`). Указатель на локальную переменную вернуть можно: компилятор сам перенесёт её в кучу (escape analysis, глава 14).
- Разыменование nil-указателя даёт panic (`invalid memory address or nil pointer dereference`).
- `new(42)` в 1.26 закрыл старую боль с опциональными полями: раньше писали хелпер `func ptr[T any](v T) *T { return &v }`.

## 7. В Go всё передаётся по значению 🟢

Это ключевое правило. При вызове функции и присваивании копируется **значение**. Разница только в том, что является значением:

| Тип | Что копируется | Видит ли вызванная функция изменения? |
|---|---|---|
| `int`, `struct`, массив | всё содержимое | нет |
| указатель | адрес | да, через `*p` |
| слайс | заголовок `{ptr, len, cap}` | изменения элементов — да; `append` с реаллокацией — нет |
| мапа, канал | указатель на внутреннюю структуру | да |
| строка | заголовок `{ptr, len}` | строки неизменяемы, вопрос не возникает |
| интерфейс | пара `{тип, данные}` | зависит от того, что внутри |

На вопрос «слайсы передаются по ссылке?» правильный ответ: **нет, копируется заголовок, а массив под ним общий**. Подробно в главе 4.

## 8. Строки, байты и руны 🟢

- `string` — неизменяемая последовательность **байт**. Обычно это UTF-8, но гарантии нет.
- `len(s)` — число **байт**: `len("привет") == 12`, потому что кириллическая буква занимает 2 байта.
- `s[i]` — байт (`uint8`). `for i, r := range s` декодирует UTF-8 и выдаёт руну (`int32`) и её байтовую позицию. Битые байты превращаются в `U+FFFD`.
- Число символов: `utf8.RuneCountInString(s)`. Развернуть строку с кириллицей можно через `[]rune(s)`.
- `string(65) == "A"`, а не `"65"` (vet предупредит). Число в строку переводят через `strconv.Itoa` или `strconv.FormatInt`, обратно через `strconv.Atoi`.
- Конкатенация `+=` в цикле — это O(n²): каждый раз новая строка и копия. Правильно использовать `strings.Builder` (с `Grow`, если размер известен) или `strings.Join`.

```go
var sb strings.Builder
sb.Grow(len(parts) * 8)
for i, p := range parts {
    if i > 0 {
        sb.WriteByte(',')
    }
    sb.WriteString(p)
}
s := sb.String() // без копии: Builder отдаёт свой буфер
```

- Сырые строки в обратных кавычках: `` `C:\path\n` `` — без экранирования, можно в несколько строк. Удобно для SQL и регулярок.
- Пакеты: `strings` (`Cut`, `Fields`, `EqualFold`, `HasPrefix`), `strconv`, `unicode/utf8`, `bytes` (то же для `[]byte`).

## 9. Сравнимость 🟡

- Сравнимы (`==`): базовые типы, указатели, каналы, интерфейсы, массивы и структуры из сравнимых элементов.
- **Несравнимы:** слайсы, мапы, функции. Их можно сравнить только с `nil`. Значит, они не годятся в ключ мапы.
  Для сравнения есть `slices.Equal`, `maps.Equal`, `bytes.Equal`, в тестах — `reflect.DeepEqual` или `cmp.Diff`.
- **Сравнение двух интерфейсов, в которых лежит несравнимый динамический тип, паникует в рантайме:**
  ```go
  var a, b any = []int{1}, []int{1}
  fmt.Println(a == b) // panic: comparing uncomparable type []int
  ```

## Под капотом 🔴

- Строка в памяти — `{ptr, len}` (16 байт на amd64). Литералы лежат в read-only сегменте бинарника.
- Подстрока `s[a:b]` — новый заголовок **без копии**. Это безопасно только благодаря неизменяемости. Обратная сторона:
  маленькая подстрока держит в памяти всю исходную строку. Если кусок нужен надолго, используй `strings.Clone`.
- `[]byte(s)` и `string(b)` **копируют**, иначе через слайс можно было бы изменить «неизменяемую» строку. Компилятор убирает копию там,
  где результат не переживает выражение: `m[string(b)]`, `string(b) == "x"`, `for range []byte(s)`. Для коротких строк есть буфер на стеке на 32 байта.
- `a + b + c` компилируется в один вызов `concatstrings`: сначала суммарная длина, потом одна аллокация.
- Подробнее: [INTERNALS.md §2](../01-language/INTERNALS.md#2-строка).

## Ловушки

- `x, err := f()` во вложенном блоке затеняет внешний `err`.
- `for i := 0; i < len(s); i++ { s[i] }` по строке с кириллицей идёт по байтам, а не по символам.
- `time.Sleep(n * time.Second)`, где `n int`, не компилируется; нужен `time.Duration(n) * time.Second`.
- `uint` при вычитании уходит в огромное число: `var u uint; u - 1 == 18446744073709551615`. Поэтому `len()` возвращает `int`, а не `uint`.
- Деньги во `float64`.
