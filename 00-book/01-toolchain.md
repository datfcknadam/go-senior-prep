# Глава 1. Тулчейн, модули, первая программа

## Зачем

После главы ты понимаешь, из чего состоит Go-проект, как собирается бинарник и откуда берутся зависимости.
На собеседовании это редко спрашивают отдельно, зато регулярно всплывает в разговоре: «как вы обновляете зависимости»,
«что такое `go.sum`», «зачем `internal`», «как собираете образ».

---

## 1. Философия языка 🟢

Go спроектировали в Google в 2007–2009 годах под конкретные боли: долгая сборка C++, сложность языка, неудобная многопоточность.
Отсюда решения, которые объясняют почти всё остальное в книге:

| Решение | Почему |
|---|---|
| мало ключевых слов (25), одна форма цикла | код читают чаще, чем пишут; любой код в компании выглядит одинаково |
| `gofmt` — единственный стиль | споры о форматировании исчезают |
| статическая типизация, быстрая компиляция | безопасность без потери скорости итераций |
| ошибки — значения, без исключений | поток управления виден в коде явно |
| композиция вместо наследования | меньше связности, проще менять |
| горутины и каналы в языке | конкурентность — норма для сервера, а не библиотека |
| GC и один статический бинарник | простая эксплуатация: скопировал файл, и он работает |

## 2. Первая программа 🟢

```go
// main.go
package main

import (
    "fmt"
    "os"
)

func main() {
    name := "мир"
    if len(os.Args) > 1 {
        name = os.Args[1]
    }
    fmt.Printf("Привет, %s!\n", name)
}
```

```bash
go mod init example.com/hello   # создать модуль
go run .                        # скомпилировать во временный каталог и запустить
go build -o hello .             # собрать бинарник
./hello Gopher
```

- Исполняемая программа — это пакет `main` с функцией `main()` без аргументов и результата.
- Аргументы командной строки лежат в `os.Args`, код выхода задаёт `os.Exit(code)`. Возврат из `main` означает код 0.
- Когда `main` возвращается, процесс завершается **сразу**, не дожидаясь остальных горутин (глава 10).

## 3. Пакеты 🟢

- **Пакет** — это каталог с `.go`-файлами, у которых одинаковая строка `package x`. Компилируется пакет целиком, а не файл.
- Импортируют пакет по **пути**: путь модуля плюс подкаталог (`example.com/hello/internal/storage`).
  Используют по **имени**, то есть по последнему элементу пути, если в `package` не указано другое.
- **Видимость:** с заглавной буквы — экспортируется (`User`, `Save`), со строчной — видна только внутри пакета. Модификаторов `public/private` нет.
- Неиспользуемый импорт или неиспользуемая локальная переменная — **ошибка компиляции**. Так кодовая база не обрастает мусором.
- Циклические импорты запрещены. Если два пакета нужны друг другу, это сигнал, что границы проведены неправильно (глава 8).

```go
import (
    "fmt"
    stdlog "log"            // алиас при конфликте имён
    _ "net/http/pprof"      // импорт ради init(): регистрирует хендлеры
    . "math"                // импорт в текущее пространство имён — не делай так
)
```

## 4. Модули 🟢

**Модуль** — единица версионирования: дерево пакетов с файлом `go.mod` в корне.

```
module example.com/promo

go 1.26

require (
    github.com/jackc/pgx/v5 v5.7.1
    golang.org/x/sync v0.10.0
)

require (                          // косвенные зависимости
    github.com/jackc/puddle/v2 v2.2.2 // indirect
)

replace example.com/billing => ../billing  // локальная подмена при разработке

tool golang.org/x/tools/cmd/stringer       // 1.24+: инструменты проекта как зависимости
```

- Директива `go 1.26` — **минимальная версия языка**. Она меняет семантику: например, переменные цикла на каждой итерации появились при `go ≥ 1.22` (глава 3).
- `toolchain go1.26.1` — какой тулчейн скачать, если локальный старше (`GOTOOLCHAIN`).
- `go.sum` хранит криптографические хеши каждого модуля. Это защита от подмены, а не lock-файл: версии фиксирует сам `go.mod`.
- **Minimal Version Selection (MVS).** Go выбирает **минимальную** версию, которая удовлетворяет всем требованиям графа,
  а не «последнюю совместимую», как npm. Поэтому сборка воспроизводима без lock-файла: новая версия зависимости
  не подтянется сама, пока кто-то явно её не потребует.
- **Семантическое версионирование и import compatibility rule:** если API ломается, у модуля меняется путь — `github.com/jackc/pgx/v5`.
  `v1` и `v5` для Go — разные модули, их можно импортировать одновременно.
- Прокси и checksum DB: `GOPROXY=https://proxy.golang.org`, `GOSUMDB=sum.golang.org`. Для приватных репозиториев компании — `GOPRIVATE=gitlab.company.ru/*`.

```bash
go get github.com/jackc/pgx/v5@v5.7.1   # добавить или обновить
go get -u ./...                         # обновить всё до minor/patch
go mod tidy                             # убрать лишнее, добавить недостающее
go mod why -m golang.org/x/text         # кто тянет зависимость
go list -m all                          # итоговый граф версий
go mod vendor                           # копия зависимостей в vendor/
```

**Workspaces** (`go work init ./svc ./lib`) позволяют разрабатывать несколько модулей сразу без `replace` в `go.mod`. Файл `go.work` в репозиторий обычно не коммитят.

## 5. Команды, которые нужны каждый день 🟢

| Команда | Что делает |
|---|---|
| `go build ./...` | собирает всё, бинарник получается только для `main` |
| `go test ./...` | тесты (глава 9); `-race`, `-run`, `-count=1`, `-cover` |
| `go vet ./...` | статический анализ: printf-форматы, копирование мьютексов, недостижимый код |
| `gofmt -l .` / `go fmt` | форматирование |
| `go doc fmt.Printf` | документация в терминале |
| `go env GOROOT GOPATH` | переменные окружения тулчейна |
| `go generate ./...` | запускает команды из комментариев `//go:generate` (моки, stringer, sqlc) |
| `go fix ./...` | автоматические «модернизации» кода под новую версию языка |
| `go tool pprof`, `go tool trace` | профилирование (глава 15) |

Обязательный внешний минимум: **golangci-lint** (агрегатор линтеров: `errcheck`, `staticcheck`, `govet`, `gosec`, `revive`) и `govulncheck`,
который ищет известные уязвимости в реально вызываемом коде, а не просто в `go.mod`.

## 6. Сборка 🟡

- `GOOS=linux GOARCH=amd64 go build` — кросс-компиляция без всяких тулчейнов: компилятор Go сам умеет все платформы.
- `CGO_ENABLED=0` — полностью статический бинарник без libc. Его можно положить в `scratch` или `distroless`.
- `-ldflags="-s -w"` убирает таблицу символов и DWARF, бинарник становится меньше.
  `-ldflags="-X main.version=1.2.3"` подставляет значение строковой переменной при сборке.
- `-trimpath` убирает локальные пути из бинарника (воспроизводимость).
- `go version -m ./bin` показывает, с какими модулями и флагами собран бинарник, а изнутри то же даёт `debug.ReadBuildInfo()`.
- **Build tags:** `//go:build linux && !cgo` в первой строке файла. Этот репозиторий так и устроен: `task.go` с `//go:build !solution`,
  а `solution.go` с `//go:build solution`, и `go test -tags solution` переключает реализацию.

Типичный Dockerfile сервиса:

```dockerfile
FROM golang:1.26 AS build
WORKDIR /src
COPY go.mod go.sum ./
RUN go mod download                 # отдельный слой: кеш зависимостей
COPY . .
RUN CGO_ENABLED=0 go build -trimpath -ldflags="-s -w" -o /app ./cmd/server

FROM gcr.io/distroless/static
COPY --from=build /app /app
ENTRYPOINT ["/app"]
```

## Под капотом 🔴

- Компилятор (`cmd/compile`) проходит путь: парсинг → проверка типов → IR → инлайнинг и escape analysis → SSA → оптимизации → машинный код.
  Флаг `-gcflags=-m` печатает решения инлайнинга и escape analysis (глава 14), а `-gcflags=-S` выводит ассемблер.
- Почему компиляция быстрая: нет заголовочных файлов, импорты не транзитивны (объектный файл пакета уже содержит всё про его экспорт),
  циклов нет, поэтому граф пакетов собирается параллельно, а результаты кешируются в `GOCACHE`.
- Бинарник содержит рантайм: планировщик, GC, аллокатор. Поэтому «hello world» весит около 2 МБ.

## Ловушки

- Код в `main` завершился, а горутины ещё работают: их просто убьют, без `defer` и без сброса буферов.
- `go get` без `@версии` внутри модуля обновляет зависимость, а не только скачивает её.
- `replace` на локальный путь, случайно закоммиченный в `go.mod`, ломает сборку у всех остальных.
- Импорт приватного репозитория без `GOPRIVATE` уходит в публичный прокси и падает (или светит название репозитория).

## Закрепление

Упражнения запускаются прямо в панели (`make panel`, эта глава): правь код в редакторе и жми ▶ или <kbd>⌘/Ctrl+Enter</kbd>. Упражнение засчитывается, когда вывод совпал с ожидаемым; конкурентные прогоняются с `-race`. Подсказки открываются по одной — сначала попробуй без них.

```go
// exercise: Глаголы fmt
// expect: {7 Велосипед}
// expect: {ID:7 Title:Велосипед}
// expect: main.Ad{ID:7, Title:"Велосипед"}
// expect: main.Ad
// expect: "Велосипед"
// expect: [   42] [3.14]
// hint: %v — значение, %+v — с именами полей, %#v — в синтаксисе Go, %T — тип, %q — строка в кавычках.
// hint: Ширина и точность: %5d выравнивает число по правому краю в 5 символов, %.2f оставляет два знака.
package main

import "fmt"

type Ad struct {
	ID    int
	Title string
}

func main() {
	a := Ad{ID: 7, Title: "Велосипед"}
	// Замени каждый ? на глагол, чтобы вывод совпал с ожидаемым.
	fmt.Printf("?\n", a)
	fmt.Printf("?\n", a)
	fmt.Printf("?\n", a)
	fmt.Printf("?\n", a)
	fmt.Printf("?\n", a.Title)
	fmt.Printf("[?] [?]\n", 42, 3.14159)
}
```

```go
// exercise: Почини сборку
// expect: sum = 6
// hint: Неиспользуемая переменная — ошибка компиляции, а не предупреждение. Ненужное значение range замени на _.
// hint: Printf без аргумента для %d напечатает %!d(MISSING). go vet ловит это до запуска — поэтому vet стоит в CI.
package main

import "fmt"

func main() {
	nums := []int{1, 2, 3}
	total := 0
	for i, n := range nums {
		total += n
	}
	fmt.Printf("sum = %d\n")
}
```
