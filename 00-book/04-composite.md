# Глава 4. Составные типы: массивы, слайсы, мапы, структуры

## Зачем

Слайсы и мапы — самые используемые структуры данных и самая частая тема вопросов «как устроено». На senior-уровне ответ
«слайс растёт в два раза» недостаточен: от тебя ждут устройство, причины решений и следствия для кода и памяти.

---

## 1. Массивы 🟢

```go
var a [3]int            // [0 0 0]
b := [...]string{"x", "y"} // длину считает компилятор
c := a                  // КОПИЯ всех элементов
```

- Длина — часть типа: `[3]int` и `[4]int` — разные типы.
- Массив — значение: при присваивании и передаче копируется целиком. Сравним через `==`, если сравнимы элементы, поэтому годится в ключ мапы.
- В прикладном коде напрямую встречается редко: в ключах мап (`[16]byte` для UUID), в буферах фиксированного размера, как основа слайса.

## 2. Слайсы 🟢

Слайс — **окно в массив**: указатель на первый элемент, длина и ёмкость.

```go
s := make([]int, 3, 10) // len 3, cap 10
s = append(s, 4)        // len 4
t := s[1:3]             // len 2, cap 9 — тот же массив
u := []int{1, 2, 3}     // литерал
var n []int             // nil-слайс: len 0, cap 0
```

- `append` **возвращает** новый заголовок, поэтому результат обязательно присваивают: `s = append(s, x)`.
- Если `len < cap`, `append` пишет в существующий массив. Иначе выделяет новый, побольше, и копирует данные.
- `copy(dst, src)` копирует `min(len(dst), len(src))` элементов, корректно работает с перекрытием и возвращает количество скопированных.
- Предвыделяй, когда размер известен: `make([]T, 0, n)`. Без этого 1000 вызовов `append` дают около 10 реаллокаций.

### Aliasing — главный источник багов 🟡

```go
a := make([]int, 3, 10)
b := append(a, 1) // пишет в a[3] — общий массив
c := append(a, 2) // ПЕРЕТИРАЕТ то же место: b[3] == 2
```

```go
func addItem(items []string) {
    items = append(items, "x") // вызывающий не увидит: изменили локальную копию заголовка
}
```

Лечится так:
- полное слайс-выражение `a[lo:hi:max]` ограничивает cap, и `append` вынужден копировать: `b := append(a[:len(a):len(a)], 1)`;
- явная копия `slices.Clone(a)`;
- функция возвращает новый слайс вместо изменения аргумента.

### nil-слайс и пустой слайс

`var s []int` и `s := []int{}` ведут себя одинаково для `len`, `append`, `range`. Отличаются в трёх местах:
`s == nil`, `reflect.DeepEqual`, и JSON: `null` против `[]`. Для API это важно: фронтенду обычно нужен `[]`.

### Пакет slices (1.21+)

```go
slices.Sort(s)
slices.SortFunc(users, func(a, b User) int { return cmp.Compare(a.Age, b.Age) })
i, found := slices.BinarySearch(s, 42)
slices.Contains(s, x); slices.Index(s, x)
s = slices.Compact(s)        // убрать соседние дубли
s = slices.Delete(s, i, j)   // с 1.22 зануляет хвост
s = slices.Insert(s, i, v)
c := slices.Clone(s)
for chunk := range slices.Chunk(s, 100) {} // 1.23: батчи по 100
```

Плюс встроенные функции `min`, `max`, `clear` (1.21).

### Удаление

```go
s[i] = s[len(s)-1]; s = s[:len(s)-1] // O(1), порядок не сохраняется
s = slices.Delete(s, i, i+1)          // O(n), порядок сохраняется
```

Фильтрация на месте без аллокации:

```go
out := s[:0]
for _, v := range s {
    if keep(v) {
        out = append(out, v)
    }
}
clear(s[len(out):]) // занулить хвост, чтобы не держать указатели
s = out
```

## 3. Мапы 🟢

```go
m := make(map[string]int, 100) // подсказка ёмкости — меньше ростов
m["a"] = 1
v := m["b"]          // 0 — отсутствующий ключ даёт zero value
v, ok := m["b"]      // ok == false
delete(m, "a")       // удаление отсутствующего ключа — не ошибка
clear(m)             // удалить всё
set := map[int64]struct{}{} // множество: значение занимает 0 байт
```

- Ключ должен быть **сравнимым** (глава 2).
- Порядок обхода **намеренно случаен**. Детерминированный обход: `for _, k := range slices.Sorted(maps.Keys(m))`.
- **nil-мапа:** чтение возвращает zero value, `len` работает, `range` работает, а **запись даёт panic**.
- `&m[k]` не компилируется. `m[k].Field = v` для структуры не компилируется. Храни указатели или перезаписывай структуру целиком.
- Удалять во время `range` безопасно. Ключ, добавленный во время `range`, может попасть в обход, а может и не попасть.
- **Мапа не потокобезопасна.** Конкурентная запись даёт `fatal error: concurrent map writes`. Это не panic, `recover` не поможет.
  Решения: `Mutex` + map, шардирование, `sync.Map` для узких сценариев (глава 11).
- **Мапа не сжимается** после `delete`. Если она пиково выросла до миллионов элементов, пересоздай её.

## 4. Структуры 🟢

```go
type User struct {
    ID        int64     `json:"id" db:"id"`
    Name      string    `json:"name"`
    CreatedAt time.Time `json:"created_at"`
    password  string    // неэкспортируемое: не видно ни другим пакетам, ни encoding/json
}

u := User{ID: 1, Name: "Анна"} // всегда указывай имена полей
p := &User{ID: 2}               // указатель на литерал
p.Name = "Борис"                // автоматическое разыменование
anon := struct{ X, Y int }{1, 2}
```

- **Теги** — строковые метаданные, их читает рефлексия: `encoding/json`, драйверы БД, валидаторы. `json:"name,omitempty"`, `json:"-"`.
- Структура из сравнимых полей сравнима через `==` и годится в ключ мапы: `map[struct{ UserID, AdID int64 }]bool`.
- Пустая структура `struct{}` весит 0 байт. Её используют в множествах и сигнальных каналах `chan struct{}`.

### Встраивание (embedding) 🟢

```go
type Base struct{ ID int64 }
func (b Base) Describe() string { return fmt.Sprint("id=", b.ID) }

type Ad struct {
    Base         // встроенное поле: имя поля — Base
    Title string
}

ad := Ad{Base: Base{ID: 7}, Title: "Диван"}
ad.ID          // продвинутое поле, то же что ad.Base.ID
ad.Describe()  // продвинутый метод
```

Это **композиция, а не наследование**. Ресивером продвинутого метода остаётся внутренний тип, виртуальных вызовов нет: если `Base.Describe`
вызовет `b.Name()`, вызовется `Base.Name`, даже если у `Ad` есть свой `Name`. Подробно про встраивание интерфейсов — в главе 5.

## Под капотом 🔴

### Слайс

```go
type slice struct {
    array unsafe.Pointer // указатель на первый элемент окна
    len   int
    cap   int            // сколько элементов от array до конца аллокации
}                        // 24 байта на amd64
```

`s[i:j]` строит новый заголовок без копии: `array + i*elemsize`, `len = j-i`, `cap = oldcap-i`.
Следствие: **подслайс держит живым весь массив**. 10 байт из 10-мегабайтного буфера, сохранённые в долгоживущую структуру, удерживают все 10 МБ.

**Рост** (`runtime.growslice` → `nextslicecap`):
- если просят больше, чем вдвое, выделяется ровно нужный размер;
- если cap < 256, ёмкость удваивается;
- дальше `newcap += (newcap + 3*256) / 4`: плавный переход от ×2 к ×1.25;
- итог в байтах **округляется вверх до size class** аллокатора (глава 14), поэтому cap бывает «странным»: `append([]int64(nil), 1,2,3,4,5)` даёт cap 6.

Почему так: геометрический рост даёт амортизированный O(1) на `append`. Для больших слайсов ×2 тратил бы до половины памяти впустую,
а ×1.25 оставляет не больше 20% хвоста. Округление до size class отдаёт в cap байты, которые аллокатор всё равно выделил бы.

### Мапа (Swiss Tables, Go 1.24+)

- Открытая адресация. Слоты сгруппированы по 8, у группы есть **контрольное слово**: 8 байт, по байту на слот.
  Байт хранит 7 бит хеша (H2) либо отметку empty/deleted.
- Поиск: старшие биты хеша (H1) выбирают стартовую группу, затем все 8 контрольных байт сравниваются с H2 **одной операцией** (SIMD или SWAR),
  и ключи сравниваются только у совпавших слотов. Встретили пустой слот — ключа нет. Иначе квадратичное пробирование по группам.
- Удаление ставит tombstone (`deleted`), если в группе нет пустых слотов, чтобы не оборвать чужие цепочки поиска.
- Мапа — это директория таблиц по ≤ 1024 слота (extendible hashing). Load factor 7/8. Переполненная таблица **делится на две**,
  поэтому пауза одной вставки ограничена даже в мапе на 100 млн ключей.
- Маленькая мапа (≤ 8 элементов) — одна группа без таблиц.
- **Старая реализация (≤ 1.23)** всё ещё спрашивается: `2^B` бакетов по 8 пар, `tophash`, overflow-бакеты, load factor 6.5, инкрементальная эвакуация.

Из устройства следуют правила:

| Правило | Почему |
|---|---|
| нельзя `&m[k]` | слот переезжает при росте или делении таблицы |
| случайный порядок | seed хеша на каждую мапу + случайный старт итератора |
| `fatal`, а не panic, при гонке | гонку замечают по флагу записи уже после порчи структуры |
| не сжимается | группы не освобождаются при удалении |

### Структура в памяти

Поля лежат подряд **в порядке объявления**, каждое выровнено по своему размеру, размер структуры кратен максимальному выравниванию:

```go
struct{ a bool; b int64; c bool } // 24 байта: 1 + 7 паддинг + 8 + 1 + 7
struct{ b int64; a bool; c bool } // 16 байт
```

Порядок важен, когда объектов миллионы. Проверка: `unsafe.Sizeof`, линтер `fieldalignment`.
GC сканирует объект только до последнего поля с указателем, а объекты совсем без указателей не сканирует вовсе (глава 14).

Подробнее: [INTERNALS.md §1, §3, §5](../01-language/INTERNALS.md).

## Ловушки

- Два `append` от одного родителя перетирают друг друга.
- Функция делает `append` в аргумент и думает, что вызывающий это увидит.
- Подслайс большого буфера хранится долго — утечка памяти.
- Запись в nil-мапу внутри структуры, созданной без конструктора: `type Cache struct{ m map[string]int }`.
- Слайс указателей «укорочен» через `s = s[:n]`, а хвост держит объекты.
- Возврат `nil`-слайса в JSON-ответе, где клиент ждёт `[]`.
