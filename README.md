# Подготовка к собеседованию на Go Senior

Обучающий репозиторий: теория + практические задачи с тестами + вопросы для собеседования.

**Начни с [учебника](00-book/README.md)**: 20 глав от тулчейна до рантайма и продакшн-сервиса, по порядку и с единым шаблоном
(теория → под капотом → ловушки → «спросят» → практика → самопроверка). Разделы `01–09` — практика, учебник ведёт к ним по ссылкам.

## Как начать

Нужен Go 1.26+. Сделай форк (или «Use this template»), склонируй его и запусти панель:

```bash
git clone https://github.com/<you>/go-senior-prep && cd go-senior-prep
make panel        # → http://localhost:8080
```

Решения пиши в своём форке, в `task.go`. Прогресс панели хранится в `.progress.json`, он в `.gitignore`.

## Веб-панель

```bash
make panel        # → http://localhost:8080
```

Панель показывает теорию, запускает тесты задач (`go test -race`) с разбором упавших тестов,
ведёт прогресс и чек-листы (головоломки, SQL-задачи, кейсы system design, mock-интервью).

**Песочница.** Каждый Go-пример в теории — редактор с подсветкой: правь и запускай прямо на странице
(<kbd>⌘/Ctrl+Enter</kbd>). Кнопки: `▶` — `go run`, `-race` — с детектором гонок, `escape` — `go build -gcflags=-m`,
`go test` — тесты и бенчмарки, если в коде есть `Test…`/`Benchmark…`. Фрагменты без `package` оборачиваются в `main`,
импорты дописывает `goimports` (если установлен). Отдельная страница «Песочница» — для своих экспериментов.

**Закрепление.** В конце каждой главы учебника — 2–3 упражнения (49 всего): заготовка, ожидаемый вывод и подсказки
по нарастающей. Сервер сверяет вывод и сам отмечает упражнение в прогрессе.

Код запускается локально на твоей машине, поэтому API принимает запросы только с localhost и только `application/json`
(защита от CSRF и DNS rebinding со сторонних сайтов).
Прогресс хранится локально в `.progress.json`. Решение по-прежнему пишешь в своей IDE, а проверяешь — в панели.
Эталон можно прогнать, не открывая его код; открыть `solution.go` — только явно, с подтверждением.

## Как устроено

Каждая практическая задача — это Go-пакет:

```
02-concurrency/workerpool/
├── README.md        # теория и условие задачи
├── task.go          # заготовка — здесь пишешь своё решение (build tag: !solution)
├── solution.go      # эталонное решение (build tag: solution) — не подглядывай сразу
└── *_test.go        # тесты, общие для заготовки и решения
```

```bash
make test                      # прогнать твои решения (сначала всё красное — это нормально)
make test-one T=./02-concurrency/workerpool
make race                      # тесты с race-детектором — обязательно для concurrency
make check                     # прогнать эталонные решения
make bench                     # бенчмарки
```

Правило: сначала решаешь сам → тесты зелёные под `-race` → только потом сравниваешь с `solution.go`.

## Работа с Claude как с ментором

В корне лежит `CLAUDE.md` — там описано, как Claude должен вести себя в этом репозитории: не выдавать решения сразу, давать подсказки, делать ревью кода и проводить mock-интервью. Примеры запросов:

- «проведи mock-интервью по конкурентности»
- «сделай ревью моего workerpool как senior на собеседовании»
- «дай подсказку по ratelimit, но не решение»
- «проведи system design интервью: лента объявлений»

## Как помочь

Нашёл ошибку в теории, придумал задачу или вопрос с собеседования — открывай [issue](https://github.com/datfcknadam/go-senior-prep/issues/new/choose) или PR.
Вопросы по темам и разбор решений — в [Discussions](https://github.com/datfcknadam/go-senior-prep/discussions). Новые задачи оформляй в том же формате:
`README.md` с условием, `task.go` с заготовкой (`panic("TODO")`), `solution.go` и тесты, которые проходят на эталоне под `-race`
(`make check`) и падают на заготовке. CI проверяет это на каждом PR, вместе с `gofmt` и `go vet`.
