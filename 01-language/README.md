# 01. Язык

На senior-собеседовании язык проверяют не «знаешь ли синтаксис», а «понимаешь ли, как это устроено внутри и где стреляет».

> Подробно: [THEORY.md](THEORY.md) — язык с разбором «почему»; [INTERNALS.md](INTERNALS.md) — как устроены слайсы, строки, мапы, интерфейсы, структуры, стек и defer внутри рантайма.

## Слайсы

- Слайс — структура из трёх слов: `{ptr *T, len int, cap int}`. Передаётся по значению, но указывает на общий массив.
- `append` пишет в общий массив, если `len < cap`, иначе аллоцирует новый (рост: ×2 до 256 элементов, дальше плавно ~×1.25, плюс округление до size class аллокатора).
- Опасность aliasing: два слайса от одного массива перезаписывают данные друг друга через `append`.
  Лечится полным слайс-выражением `s[lo:hi:max]` — тогда `cap` ограничен, и `append` обязан скопировать.
- Подслайс большого массива держит в памяти **весь** массив (утечка). Если нужен маленький кусок надолго — `slices.Clone`.
- `nil`-слайс и пустой слайс: оба `len == 0`, `append` и `range` работают одинаково, но `json.Marshal` даёт `null` против `[]`.

## Мапы

- Хеш-таблица. С Go 1.24 — Swiss Tables (группы по 8 слотов + контрольные байты, SIMD-поиск); раньше — бакеты по 8 элементов + overflow-бакеты.
- Порядок итерации намеренно случаен.
- Брать адрес элемента нельзя (`&m[k]` — ошибка компиляции): при росте элементы переезжают.
- Не потокобезопасна: конкурентная запись → `fatal error: concurrent map writes` (это не panic, `recover` не поможет).
- Мапа не уменьшается после удаления элементов — память остаётся занятой. Решение — пересоздать мапу.
- Запись в `nil`-мапу → panic, чтение из неё → нулевое значение.

## Интерфейсы

- Непустой интерфейс — `iface{tab *itab, data unsafe.Pointer}`, пустой (`any`) — `eface{_type, data}`.
- **Nil-интерфейс ≠ интерфейс, в котором лежит nil-указатель.** Классика:
  ```go
  func find() error {
      var e *MyErr = nil
      return e // err != nil — true!
  }
  ```
- Интерфейсы объявляет потребитель, а не поставщик («accept interfaces, return structs»).
- Method set: значение `T` имеет методы с ресивером `T`, а `*T` — и `T`, и `*T`. Поэтому `T` с методом на `*T` не реализует интерфейс.

## Ошибки

- `%w` в `fmt.Errorf` оборачивает ошибку; `errors.Is` ищет конкретное значение по цепочке, `errors.As` — тип.
- Sentinel-ошибки (`var ErrNotFound = errors.New(...)`) — часть публичного API пакета, менять их нельзя.
- `errors.Join` (Go 1.20+) — несколько ошибок сразу.
- Ошибку либо обрабатываешь, либо возвращаешь с контекстом — но не логируешь и возвращаешь одновременно (иначе дубли в логах).
- `panic` — для невозможных состояний и ошибок программиста, не для бизнес-логики.

## defer / panic / recover

- Аргументы `defer` вычисляются в момент объявления, а выполняется — LIFO при выходе из функции.
- `defer` может менять именованные возвращаемые значения.
- `recover` работает только при вызове напрямую внутри отложенной функции.
- Паника в горутине без `recover` роняет весь процесс — `recover` в другой горутине не спасёт.

## Дженерики

- Ограничения типов: `comparable`, `cmp.Ordered`, свои — `interface{ ~int | ~string }`.
- Реализация: GC shape stenciling + словари — одна копия кода на «форму» типа (все указатели — одна форма).
  Поэтому дженерики через указатели могут быть медленнее ручной специализации.
- Когда использовать: контейнеры, утилиты над слайсами и мапами. Когда нет: если хватает обычного интерфейса.
