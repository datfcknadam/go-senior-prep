# Теория: язык Go — подробно

Расширенная версия [README](README.md). Здесь написано, как всё устроено внутри и о чём спросят следом.
В конце каждого блока есть раздел «Спросят», где собраны вопросы так, как их задают на интервью.

---

## 1. Типы, значения, передача

- **В Go всё передаётся по значению.** Слайс, мапа, канал, функция и интерфейс тоже, просто их значение — это маленький заголовок
  или указатель на общие данные. Поэтому функция видит изменения элементов слайса, но не видит `append`, если он сделал реаллокацию.
- **Zero value** есть у каждого типа, и хороший API делает нулевое значение полезным: `sync.Mutex{}`, `bytes.Buffer{}` и `strings.Builder{}` готовы к работе сразу.
- **Определение типа и алиас — разные вещи:**
  ```go
  type MyInt int    // новый тип: методы int не наследует, нужна явная конверсия
  type Alias = int  // то же самое имя для int
  ```
  С Go 1.24 бывают и дженерик-алиасы: `type Set[T comparable] = map[T]struct{}`.
- **Underlying type** определяет, какие операции и конверсии разрешены. `~int` в ограничениях означает «любой тип с underlying `int`».
- **Нетипизированные константы** имеют произвольную точность до момента использования. Поэтому `const big = 1 << 100` компилируется, а `int(big)` уже нет.
- `iota` — счётчик внутри блока `const`, удобен для enum и битовых флагов: `1 << iota`.
- **Целые числа** переполняются циклически, без паники. Деление целого на ноль даёт panic, а для float получится `+Inf` или `NaN`.
  `NaN != NaN`, поэтому NaN-ключ в мапе нельзя ни найти, ни удалить, его убирает только `clear`.
- **Сравнимость.** Сравнимы базовые типы, указатели, каналы, интерфейсы, массивы и структуры из сравнимых полей.
  Слайсы, мапы и функции несравнимы, их можно сравнить только с `nil`. **Сравнение двух интерфейсов, внутри которых лежит
  несравнимый динамический тип, паникует в рантайме.**

**Спросят:** «передаются ли слайсы по ссылке?» Нет: копируется заголовок, а массив общий. «Чем `type A B` отличается от `type A = B`?»

## 2. Строки

- Строка — это `{ptr, len}`, неизменяемая последовательность **байт**, необязательно в UTF-8.
- `len(s)` возвращает число байт. `for i, r := range s` идёт по рунам и декодирует UTF-8 (на битых байтах получится `U+FFFD`), а `s[i]` возвращает байт.
  Число символов считается так: `utf8.RuneCountInString(s)`.
- `string(65)` даёт `"A"`, а не `"65"` (vet об этом предупреждает). Для числа в строку есть `strconv.Itoa`.
- Конверсии `[]byte(s)` и `string(b)` в общем случае **копируют**. Компилятор обходится без копии, когда:
  ищет по мапе `m[string(b)]`, сравнивает `string(b) == "x"`, делает `for range []byte(s)` или конкатенирует во временную строку, которая не убегает.
  Без копии через unsafe: `unsafe.String(unsafe.SliceData(b), len(b))`. Такое допустимо, только если `b` больше никто не меняет.
- Конкатенация `+=` в цикле работает за O(n²). Правильно так: `strings.Builder` (и `Grow`, если размер известен) или `strings.Join`.
- Подстрока `s[a:b]` держит в памяти всю исходную строку. Если кусок нужен надолго, используй `strings.Clone`.

**Спросят:** «Что выведет `len("привет")`?» Ответ: 12. «Как развернуть строку с кириллицей?» Через `[]rune`.

## 3. Массивы и слайсы

- Массив `[N]T` — это значение. При присваивании и передаче в функцию копируется целиком. Длина входит в тип.
- Слайс — `{array unsafe.Pointer, len, cap int}` (24 байта на amd64).
- **Как растёт `append`** (Go 1.18+, `runtime.growslice`): до 256 элементов ёмкость удваивается,
  дальше `newcap += (newcap + 3*256) / 4`, то есть плавный переход от ×2 к ×1.25. После этого размер **округляется вверх до size class** аллокатора,
  поэтому cap бывает «странным», например 5 → 6 для `[]int64`, если ёмкость не хватает.
  Если запрошено больше, чем вдвое (`append(s, many...)`), берётся ровно нужный размер, тоже с округлением.
- **Aliasing:**
  ```go
  a := make([]int, 3, 10)
  b := append(a, 1) // пишет в общий массив
  c := append(a, 2) // перетирает b[3]!
  ```
  Лечится полным выражением `a[:len(a):len(a)]`, которое заставляет `append` копировать, или явным `slices.Clone`.
- `copy(dst, src)` копирует `min(len)` элементов, корректно работает с перекрывающимися областями и возвращает число скопированных.
- Удаление без сохранения порядка за O(1): `s[i] = s[len(s)-1]; s = s[:len(s)-1]`. С сохранением порядка: `slices.Delete`,
  который с Go 1.22 **зануляет хвост**, чтобы не держать указатели.
- **Утечки:** подслайс огромного буфера не даёт GC его собрать. Слайс указателей после «удаления» через `s = s[:n]` продолжает держать объекты в хвосте.
- Пакет `slices` (1.21+): `Sort`, `SortFunc`, `BinarySearch`, `Contains`, `Index`, `Compact`, `Clone`, `Grow`, `Reverse`, `Max`.
  Встроенные функции `min`, `max`, `clear` тоже появились в 1.21.
- Слайс конвертируется в массив: `[4]int(s)` с Go 1.20 (паникует, если `len < 4`), `(*[4]int)(s)` с 1.17.
- `nil`-слайс и `[]T{}` ведут себя одинаково везде, кроме `== nil`, `reflect.DeepEqual` и JSON (`null` против `[]`).

**Спросят:** «Почему функция, сделавшая `append`, не изменила слайс у вызывающего?» «Сколько аллокаций в цикле `append` на 1000 элементов
без предвыделения?» Около log₂-числа, примерно 10. «Как избежать?» `make([]T, 0, n)`.

## 4. Мапы

- Переменная мапы — указатель на внутреннюю структуру, поэтому изменения видны в вызванной функции.
- **Swiss Tables (Go 1.24+)**: слоты сгруппированы по 8, у группы есть **контрольное слово** — 8 байт с 7 битами хеша (H2) на каждый слот.
  Поиск сравнивает сразу 8 контрольных байт (SIMD или битовые трюки), а затем проверяет ключи только у совпавших слотов. Пробирование квадратичное, по группам.
  Мапа разбита на несколько таблиц по ≤1024 слота с директорией (extendible hashing), и при росте делится одна таблица.
  Так рост остаётся **инкрементальным** и не превращается в один длинный rehash. Load factor 7/8.
- **Старая реализация (до 1.24)** всё ещё спрашивается: `hmap` → `2^B` бакетов по 8 пар, `tophash` из 8 старших байт хеша,
  overflow-бакеты, load factor 6.5, эвакуация при росте происходит постепенно, во время записей.
- Хеш **рандомизирован seed'ом** для защиты от hash flooding, отсюда и случайный порядок итерации. Его специально дополнительно перемешивают,
  чтобы никто на порядок не полагался.
- `&m[k]` не компилируется, потому что значения переезжают при росте. По той же причине нельзя `m[k].field = v` для struct-значения:
  нужно хранить указатель или перезаписывать структуру целиком.
- **Удалять во время `range` можно**, это безопасно. Добавленный во время `range` ключ может попасть в итерацию, а может и не попасть.
- Конкурентная запись или запись одновременно с чтением дают `fatal error: concurrent map writes` / `concurrent map read and map write`.
  Это **не panic**, `recover` его не поймает. Рантайм ловит такое лишь иногда (флаг `hashWriting`), гарантии обнаружения нет.
- Мапа **не сжимается** после `delete`. Если она пиково выросла до миллионов элементов, пересоздай её.
- `map[K]struct{}` — множество: значение весит 0 байт.
- Предвыделение `make(map[K]V, n)` избавляет от ростов.
- Пакет `maps` (1.21+), итераторы `maps.Keys`/`maps.Values` (1.23, возвращают `iter.Seq`), `slices.Sorted(maps.Keys(m))` дают детерминированный обход.

**Спросят:** «Как устроена мапа?» Расскажи и про Swiss tables, и про старые бакеты. «Почему порядок случаен?» «Почему нельзя взять адрес?»
«Как сделать потокобезопасную мапу?» Варианты: `Mutex` + `map`, шардирование, `sync.Map` (с оговорками, см. конкурентность).

## 5. Структуры и память

- **Выравнивание и паддинг:** поля выравниваются по своему размеру, структура по максимальному полю.
  ```go
  struct{ a bool; b int64; c bool } // 24 байта
  struct{ b int64; a bool; c bool } // 16 байт
  ```
  Это важно, когда в памяти миллионы объектов. Проверка: `unsafe.Sizeof`, линтер `fieldalignment`.
- `struct{}` занимает 0 байт, и все такие значения могут иметь один адрес. Применяется в сигнальных каналах `chan struct{}` и в множествах.
  Ловушка: пустое **последнее** поле структуры получает паддинг, иначе указатель на него смотрел бы за пределы объекта.
- **Встраивание (embedding)** — это композиция, а не наследование. Методы продвигаются наружу, но ресивером остаётся внутренний тип.
  «Переопределения» с виртуальным вызовом нет: если метод `Base.Hello()` вызывает `b.Name()`, он вызовет `Base.Name`, а не метод внешней структуры.
- Встроить интерфейс в структуру — это способ частично реализовать интерфейс (часто встречается в моках). Невызванные методы паникуют на nil.
- **Копирование структур с `sync.Mutex`** ломает синхронизацию. `go vet` (copylocks) ругается, если в структуре есть `noCopy` или `Lock/Unlock`.
  Отсюда правило: структуры с мьютексом передают по указателю, и методы у них на `*T`.
- Атомарный `int64` на 32-битных платформах должен быть выровнен на 8. Типы `atomic.Int64` решают это сами.

## 6. Функции, замыкания, методы

- Функции — значения первого класса. Замыкание захватывает **переменную**, а не её значение.
- **Переменные цикла (Go 1.22+)** создаются заново на каждой итерации. До 1.22 классический баг выглядел так:
  ```go
  for _, v := range xs { go func() { use(v) }() } // раньше: у всех последнее v
  ```
  На собесе нужно сказать обе вещи: что было и что изменилось. Правило зависит от версии `go` в `go.mod`.
- `range` по целому числу `for i := range 10` есть с 1.22. По функциям-итераторам `for x := range seq` — с 1.23:
  `iter.Seq[V] = func(yield func(V) bool)`. Если `yield` вернул `false`, итератор обязан остановиться.
- **Ресивер значение или указатель.** Указатель нужен, если метод меняет состояние, структура большая или внутри есть мьютекс.
  Внутри одного типа не смешивай.
  - Method set у `T` — методы с ресивером `T`. У `*T` — методы и с `T`, и с `*T`.
  - Метод на `*T` можно вызвать у **адресуемого** значения: `v.M()` превращается в `(&v).M()`. У значения в мапе или у возврата функции так нельзя.
- **Method value** `f := obj.M` фиксирует ресивер в момент вычисления. Для ресивера-значения это копия.
- **Порядок инициализации пакета:** сначала импорты (рекурсивно, каждый пакет один раз), потом переменные пакета в порядке зависимостей, затем `init()` в порядке появления в файлах.
  Если `init` с побочными эффектами, считай это code smell: такое трудно тестировать.

## 7. Интерфейсы

- `iface{tab *itab, data unsafe.Pointer}`, где `itab` = (тип интерфейса, динамический тип, таблица методов). Она кешируется глобально.
  Пустой интерфейс устроен как `eface{_type, data}`.
- Значение, которое не помещается в указатель, при упаковке в интерфейс **аллоцируется в куче**. Мелкие целые 0–255 и нулевые значения берутся из
  статических таблиц и не аллоцируются.
- **Nil-интерфейс** — это только когда *и тип, и данные* nil:
  ```go
  var p *MyErr          // nil-указатель
  var err error = p     // err != nil, потому что тип *MyErr задан
  ```
  Правило: функция, возвращающая `error`, на успех пишет `return nil`, а не возвращает типизированную nil-переменную.
- Вызов метода через интерфейс — косвенный вызов, который нельзя заинлайнить. Компилятор умеет девиртуализацию, если тип известен,
  а PGO девиртуализирует горячие вызовы.
- **Type assertion:** `v := i.(T)` паникует при несовпадении, `v, ok := i.(T)` не паникует. Type switch: `switch x := i.(type)`.
- Проверка на этапе компиляции: `var _ Storage = (*pgStorage)(nil)`.
- **Дизайн:** интерфейсы маленькие (1–3 метода), объявляются **у потребителя**. Правило «accept interfaces, return structs».
  Не делай интерфейс «на всякий случай» под единственную реализацию, если он не нужен для тестов.
- Встраивание интерфейсов (`io.ReadWriter`) и опциональные интерфейсы через assertion (`if f, ok := w.(http.Flusher)`).

**Спросят:** «Почему `err != nil`, хотя я вернул nil?» Это вопрос номер один. «Сколько стоит вызов через интерфейс?»
«Где объявлять интерфейс?» «Чем `any` отличается от дженерика?»

## 8. Ошибки

- `error` — это интерфейс `Error() string`. Ошибка — обычное значение, исключений нет.
- Три вида ошибок:
  1. **Sentinel:** `var ErrNotFound = errors.New("not found")`. Проверяется через `errors.Is`. Это часть публичного API.
  2. **Тип:** `type ValidationError struct{ Field string }`. Проверяется через `errors.As(err, &target)`, где target — указатель на переменную типа ошибки.
     С Go 1.26 есть дженерик-вариант: `e, ok := errors.AsType[*ValidationError](err)`.
  3. **Непрозрачная:** вызывающий только проверяет `!= nil`, а поведение узнаёт через интерфейс (`interface{ Temporary() bool }`).
- **Обёртывание:** `fmt.Errorf("load user %d: %w", id, err)`. Несколько `%w` разрешены с 1.20, тогда `Unwrap() []error`. Есть ещё `errors.Join`.
- `%v` вместо `%w` разрывает цепочку. Делай так сознательно, когда не хочешь, чтобы внутренняя ошибка стала частью твоего API
  (например, не хочешь отдавать наружу `sql.ErrNoRows`).
- Кастомные `Is(target error) bool` и `As(any) bool` позволяют сравнивать ошибки по смыслу.
- **Правила на senior-уровне:**
  - Добавляй контекст на каждом уровне так, чтобы сообщение читалось как путь: `create order: reserve item 42: db: timeout`.
  - Логируй **один раз**, на границе (handler или воркер). Залогировать и при этом вернуть — значит получить дубли.
  - Ошибки слоя БД переводи в доменные (`ErrNotFound`) на границе репозитория, чтобы доменный слой не знал про `pgx`.
  - `panic` нужен для нарушенных инвариантов и ошибок программиста. В библиотеках наружу паника не выходит.
    `Must*` уместен в `init` и тестах.

## 9. defer, panic, recover

- `defer` выполняется при выходе из функции в порядке LIFO. **Аргументы вычисляются сразу**, а тело замыкания выполняется позже.
- Отложенная функция может менять именованные результаты, на этом держатся `defer func() { if err != nil { tx.Rollback() } }()` и обогащение ошибки.
- Стоимость: с 1.14 есть open-coded defers, и они почти бесплатны. Исключение — `defer` в цикле: такие копятся до конца функции,
  и это ещё и баг, если внутри закрываются файлы. Тело цикла выноси в функцию.
- `recover()` работает, только если вызван **непосредственно** в отложенной функции той горутины, которая паникует.
- Паника в горутине без recover роняет **весь процесс**. Поэтому у воркеров и хендлеров есть recover-middleware
  (`net/http` сам ловит панику в хендлере и пишет её в лог, кроме `http.ErrAbortHandler`).
- `os.Exit` и `log.Fatal` **не выполняют defer**.
- `panic(nil)` с 1.21 превращается в `*runtime.PanicNilError`, так что `recover()` больше не возвращает nil.
- Фатальные ошибки рантайма не перехватываются: concurrent map writes, нехватка памяти, переполнение стека, дедлок всех горутин.

## 10. Дженерики

- Синтаксис `func Map[T, U any](s []T, f func(T) U) []U`, типы `type Stack[T any] struct{ items []T }`.
- **Ограничение — это интерфейс-множество типов:** `interface{ ~int | ~int64 | ~string }`. Бывает смешанный вариант: `interface{ ~[]E; Len() int }`.
  Встроенные: `any`, `comparable`, `cmp.Ordered`.
- Вывод типов работает по аргументам, а с 1.21 ещё и по типу присваивания и для функций-аргументов.
- **Ограничения языка:** у методов не бывает своих type parameters. Нельзя делать type switch по `T` напрямую (только через `any(v).(type)`).
  Нет специализации. Нет ковариантности: `[]Dog` не является `[]Animal`.
  С Go 1.26 дженерик-тип может ссылаться на себя в своём списке type parameters (`type Ord[T Ord[T]] interface{ Less(T) bool }`).
- **Реализация — GC shape stenciling + dictionaries.** Код генерируется по одному экземпляру на «форму» (underlying type и размещение указателей),
  а все указательные типы делят одну форму. Методы ограничения вызываются через словарь, то есть косвенно, без инлайна.
  Вывод: дженерик по `int` быстрый, дженерик по интерфейсу или указателю может проиграть ручному коду.
- **Когда нужны:** структуры данных (кэш, очередь, множество), утилиты над слайсами, мапами и каналами, типобезопасные обёртки (`atomic.Pointer[T]`, `sync.OnceValue`).
  **Когда не нужны:** если достаточно поведения через обычный интерфейс (`io.Reader`).
