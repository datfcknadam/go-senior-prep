# Задача: ошибки

Сервисный слой получает ошибки из репозитория и должен:

1. Превращать `sql.ErrNoRows` в `*NotFoundError{Resource: "user", ID: id}`, причём так, чтобы
   `errors.Is(err, ErrNotFound)` тоже возвращал `true` (подсказка: метод `Is` у своего типа).
2. Остальные ошибки возвращать **обёрнутыми** с контекстом: `get user 42: <исходная ошибка>`.
3. Отклонять `id <= 0` ошибкой, для которой `errors.Is(err, ErrValidation)` — `true`.

Плюс функция `IsRetryable(err)`: `true`, если где-то в цепочке есть
`context.DeadlineExceeded` или ошибка с методом `Temporary() bool`, вернувшим `true`.
`context.Canceled` — **не** retryable (клиент ушёл, повторять незачем).

Вопросы:

1. Почему сравнение `err == sql.ErrNoRows` — плохая практика?
2. Когда стоит заводить свой тип ошибки, а когда хватит sentinel?
3. Как ошибки репозитория должны превращаться в HTTP-коды и где проходит эта граница?
