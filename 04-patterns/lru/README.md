# Задача: LRU-кэш с TTL

Одна из самых частых задач live coding. Сначала её просят без TTL и без потокобезопасности, потом добавляют требования.

```go
c := New[string, int](capacity, ttl, now)
c.Set("a", 1)
v, ok := c.Get("a")
c.Len()
```

- `Get` и `Set` — **O(1)**.
- При переполнении вытесняется наименее давно использованный элемент. `Get` считается использованием.
- `Set` существующего ключа обновляет значение, TTL и делает элемент самым свежим.
- Элемент старше `ttl` считается отсутствующим (`Get` → `false`) и удаляется. `ttl == 0` — без срока жизни.
- Потокобезопасность.

Структура: `map[K]*list.Element` + двусвязный список (`container/list`). Можно и свой список — тоже спросят.

Вопросы:

- Почему `Get` под `RWMutex.RLock` не сработает? (`Get` меняет порядок в списке, это запись)
- Как уменьшить contention на одном мьютексе? (шардирование по хешу ключа)
- LRU vs LFU vs ARC vs W-TinyLFU (ristretto, otter). Когда LRU плох? (скан большого объёма вымывает горячие данные)
- Локальный кэш в 50 подах — как инвалидировать? (короткий TTL, pub/sub-инвалидация, версия в ключе)
