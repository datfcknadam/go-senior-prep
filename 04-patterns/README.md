# 04. Паттерны надёжности

В крупном продукте сотни микросервисов. Любой вызов по сети может упасть, зависнуть или ответить медленно,
поэтому senior-разработчик должен уметь объяснить, как сервис ведёт себя при отказе зависимостей.

## Таймауты

- Таймаут на **каждый** сетевой вызов. `http.Client{}` без `Timeout` ждёт вечно.
- Дедлайн передаётся через `context` по всей цепочке (и между сервисами — через заголовки / gRPC deadline propagation).
- Бюджет: если у входящего запроса SLA 300 мс, нет смысла ставить 1 с на вызов зависимости.

## Retry

- Повторять только **идемпотентные** операции и только **временные** ошибки (таймаут, 503, 429, connection reset).
  Не повторять 400, 404, ошибки валидации.
- Exponential backoff **с jitter** — иначе все клиенты ретраят синхронно и добивают восстанавливающийся сервис.
- Retry budget / ограничение доли ретраев (например ≤ 10% трафика), иначе **retry storm**: 3 уровня × 3 попытки = 27× нагрузка.
- Ретраить на одном уровне стека, а не на каждом.

## Circuit breaker

- `Closed` → (порог ошибок) → `Open` (сразу отказ, зависимость отдыхает) → (таймаут) → `Half-Open` (пробные запросы) → `Closed` / `Open`.
- Плюс к нему — fallback: кэш, дефолтное значение, деградация функциональности (не показать блок «похожие объявления», но показать само объявление).

## Остальное, что нужно уметь назвать и объяснить

- **Bulkhead** — изоляция ресурсов (отдельные пулы под разные зависимости), чтобы одна медленная не съела все горутины / коннекты.
- **Load shedding** — отбрасывать запросы при перегрузке (по очереди, по латентности), отвечать 503 быстро, а не медленно.
- **Hedged requests** — послать дубль запроса, если первый не ответил за p95; берём первый ответ.
- **Идемпотентность** — `Idempotency-Key`, уникальные ограничения в БД, дедупликация консьюмеров.
- **Graceful shutdown / readiness** — сначала перестать получать трафик, потом доработать текущие запросы.
- **Кэширование** — cache-aside, write-through, инвалидация, TTL с jitter, stampede (см. `02-concurrency/singleflight`), горячие ключи.
